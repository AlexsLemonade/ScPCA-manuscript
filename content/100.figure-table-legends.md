<!-- Figure 2 -->
![**Overview of the `scpca-nf` workflow and download file structures.**](https://raw.githubusercontent.com/AlexsLemonade/scpca-paper-figures/v0.2.2/figures/compiled_figures/pngs/figure_2.png?sanitize=true){#fig:fig2 tag="2" width="7in"}

A. Overview of `scpca-nf`, the primary workflow for processing single-cell/nuclei RNA-seq data for the ScPCA Portal.
Mapping with `alevin-fry` generates a gene-by-cell count matrix, which is read into `R` and converted into a `SingleCellExperiment` (`SCE`) object (`Unfiltered SCE Object`).
Next, empty droplets are removed (`Filtered SCE Object`).
This filtered object undergoes additional post-processing, including removing low-quality cells, normalization, dimension reduction with PCA and UMAP, cell type annotation, and CNV inference (`Processed SCE Object`).
A summary QC report and a supplemental cell type report are prepared and exported.
All `SCE` files are converted to `AnnData` format and exported.

Panels B-G show abbreviated versions of figures in the summary QC report, shown here for `SCPCL000001` [@doi:10.1093/neuonc/noad207], as follows:

B. The total UMI count for each cell in the `Unfiltered SCE Object`, ordered by rank.
Points are colored by the percentage of cells that pass the empty droplets filter.

C. The per-cell number of genes detected passing the empty droplets filter against the total UMI count.
Points are colored by the percentage of mitochondrial reads.

D. `miQC` model diagnostic plot showing the per-cell percent of mitochondrial reads against the number of genes detected in the `Filtered SCE Object`.
Points are colored by the `miQC` probability that the cell is compromised.

E. The per-cell percent of mitochondrial reads against the number of genes detected.
Points are colored by whether the cell was kept or removed as determined by both `miQC` and a minimum unique gene count cutoff.

F. UMAP of log-normalized RNA expression colored by the number of genes detected.

G. UMAP of log-normalized RNA expression for the top four most variable genes, colored by the given gene's expression.
The actual summary QC report shows the top 12 most highly variable genes.

H. File download structure for an ScPCA Portal project download in `SingleCellExperiment` (`SCE`) format.
Downloads contain metadata, the three processing levels of the expression data, the summary QC report, and cell type report for all project libraries.
Bulk expression data will be provided if present in the project.

I. File download structure for an ScPCA Portal merged project download in `SCE` format.
In addition to merged object and its report, library-specific summary QC and cell type reports are provided.

<!-- Figure 3 -->
![**Consensus cell type annotation in `scpca-nf`.**](https://raw.githubusercontent.com/AlexsLemonade/scpca-paper-figures/v0.2.2/figures/compiled_figures/pngs/figure_3.png?sanitize=true){#fig:fig3 tag="3" width="7in"}

A. Expanded view of cell type annotation process within `scpca-nf`, performed on the `Processed SCE Object` (Figure {@fig:fig2}A).
`SingleR` [@doi:10.1038/s41590-018-0276-y] uses a `celldex` [@doi:10.1038/s41590-018-0276-y] reference dataset with ontology labels, `CellAssign`[@doi:10.1038/s41592-019-0529-1] uses a list of marker genes compiled from `PanglaoDB` [@doi:10.1093/database/baz046], and `SCimilarity` [@doi:10.1038/s41586-024-08411-y] uses the `SCimilarity` foundation model.
These cell typing results, along with consensus cell type annotations, are then added to the `Processed SCE Object`.
A cell type summary report with detailed information about annotation, including comparisons and diagnostic plots, is created.
Cell type annotations are also included in the `Processed AnnData Object`.

B. Diagram of ontology-aware consensus cell type annotation performed in `scpca-nf`, using T cell annotation as an example.
Numbers in parentheses indicate the cell type's number of Cell Ontology descendants.
Pairwise comparisons are made among annotations, and the consensus cell type is the latest common ancestor in Cell Ontology with the fewest descendants, indicated by the check mark.

C. Example heatmap (`SCPCL000001`) as shown in the cell type summary report comparing the consensus cell type annotations to automated annotations assigned by `SingleR`, `CellAssign`, and `SCimilarity`.
Heatmap cells are colored by the Jaccard similarity index.
A value of 1 indicates complete overlap, and 0 indicates no overlap between cells annotated with each label.
This figure shows only the top seven consensus cell type annotations with at least three cells, but cell type summary report's heatmap shows all cell types.

![**Results from benchmarking `alevin-fry` and `cellranger count` performance.**](https://raw.githubusercontent.com/AlexsLemonade/scpca-paper-figures/v0.2.2/figures/compiled_figures/pngs/figure_s1.png?sanitize=true){#fig:figS1 tag="S1" width="7in"}

C. Log total UMI counts for libraries processed with both platforms.
The total UMI count per cell between platforms broadly agree, although `alevin-fry` sometimes returned slightly higher values.
D. Log total genes detected per cell for libraries processed with both platforms.
The total number of genes detected per cell between platforms broadly agree, although `alevin-fry` sometimes returned slightly higher values.

<!-- Figure S2 -->
![**Processing additional single-cell modalities in `scpca-nf`.**](https://raw.githubusercontent.com/AlexsLemonade/scpca-paper-figures/v0.2.2/figures/compiled_figures/pngs/figure_s2.png?sanitize=true){#fig:figS2 tag="S2" width="7in"}

A. Overview of the `scpca-nf` workflow for processing CITE-seq libraries with antibody-derived tag (ADT) data.
This workflow differs from Figure {@fig:fig2}A as follows.
First, both RNA and ADT FASTQ file are input to `alevin-fry`, along with a TSV file containing ADT barcode information.
Second, during post-processing, statistics are calculated to filter cells based on ADT counts, but filtering is not performed.
ADT counts for filtering-passing cells are normalized and included in the `Processed SCE Object`.
Third, the summary QC report includes a `CITE-seq` section with information about ADT-level processing.
Fourth, the workflow exports a single `SCE` object with both RNA and ADT results but separate `AnnData` objects for RNA and ADT.

Panels B-D show example figures that appear in the CITE-seq section of the summary QC report, shown here for `SCPCL000290`.

B. Percent of per-cell mitochondrial reads against the number of genes detected.
The panel labeled "Keep" displays cells that are retained based on both RNA and ADT counts.
Other panels display cells filtered based only on the given type of count(s).

C. Density plots of the log-normalized ADT counts for the library's four most variable ADTs.

D. UMAP log-normalized RNA expression values colored by the given highly-variable ADT expression.

E. Overview of the `scpca-nf` workflow for multiplexed libraries.
This workflow differs from Figure {@fig:fig2}A as follows.
First, both an RNA and HTO FASTQ file are required as input to `alevin-fry`, along with a TSV file containing library pools information.
Second, the RNA FASTQ file, the HTO FASTQ file, and, if available, a corresponding Bulk RNA FASTQ file for each sample in the multiplexed library are provided to a demultiplexing subprocess.
The workflow calculates demultiplexing results from on HTO counts and genetic demultiplexing results if bulk RNA-seq data is available.
Demultiplexing results are stored in all exported `SCE` objects versions, but libraries themselves are not demultiplexed.
Third, only `SCE`, not `AnnData`, files are provided for multiplexed libraries.

<!-- Figure S3 -->
![**Processing other sequencing modalities and merging objects with `scpca-nf`.**](https://raw.githubusercontent.com/AlexsLemonade/scpca-paper-figures/v0.2.2/figures/compiled_figures/pngs/figure_s3.png?sanitize=true){#fig:figS3 tag="S3" width="7in"}

A. Overview of the bulk RNA-Seq workflow.
Reads are trimmed using `fastp`, and `salmon` is used to map reads and quantify counts.
Quantified expression files are grouped by project and exported as a sample-by-gene count matrix in TSV format.

B. Overview of the spatial transcriptomics workflow.
The FASTQ file and tissue and/or CytAssist image for a given library are input to `spaceranger` and returned without further processing.

C. Overview of the merged workflow.
Processed `SCE` objects in a given project are merged into a single object, including ADT counts from CITE-seq data if present, and a merged summary report is generated.
Merged objects are provided in either `SCE` or `AnnData` format.

D. Example of UMAPs as shown in the merged summary report.
Red cells are from the library of interest; other cells are in gray.
The UMAP was constructed from the merged object with equal library weighting, but no batch correction was performed.
The libraries pictured are a subset of libraries in the ScPCA project `SCPCP000003`.
For this figure specifically, the merged UMAP was constructed from these four libraries only.
The ScPCA Portal merged objects and summary reports contain all libraries in the given project.
